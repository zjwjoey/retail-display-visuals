# 场景配置与视角关系

成套项目保存一份 `scene-spec.json`，所有视角从同一份数据编译。示例见 [scene-spec.example.json](scene-spec.example.json)。独立单图不强制建立大配置；需要多视角或严格局部改造时使用。

## 最小合同

- `scene_id`：场景身份；`schema_version` 当前为1.1。
- `business`：经营类型、画面覆盖是主题专区还是完整门店、周边应有哪些品类。不自动把主题扩展全店。
- `products`：商品ID、参考路径、图中可证尺寸、款式与身份约束、包装确认状态。未知尺寸留空或null，不按像素猜实测值。
- `fixtures`：架体ID、靠墙/岛架/端头身份、朝向与邻区；模块顺序；每模块从上到下的层ID、支撑、商品ID、姿态和色组顺序。
- `views`：模式、关系、关联场景/架体/锚图、可见层位范围和允许变化。
- `assets`：参考角色和确认范围。布局锚可标 `approval: layout_only`；不能因为布局被接受就继承它的商品比例或外形错误。

示例W01/A严格为：L1盘直立 → L2盘叠放 → L3杯直立 → L4杯直立。新视角可以裁掉不需要的模块，但不能把四层合并为三层或交换L2/L3。配置记录的是可见陈列/设计，不是库存或完整SKU清单。

## 关系决定哪些内容锁定

| relation | 含义 | 检查边界 |
|---|---|---|
| anchor | 本组锚视角 | 记录批准了哪些内容、哪些问题仍未通过 |
| same_fixture | 同一架体的另一视角/细节 | 锁定架体、模块顺序、每层商品与支撑；允许镜头和裁切 |
| same_scene | 同店不同架体 | 共享环境和区域关系；不能套用同架层位逐项比对 |
| independent | 独立设计或另一实拍 | 按自身任务验收，不因不同于主墙而扣分 |

`same_fixture` 使用 `anchor_view`，且scene_id与fixture_id必须与锚相同；`same_scene`场景须相同但可指向不同架体；独立局部改造可用另一个scene_id。视图的 `level_selection` 为all或如 `{"A":["L1","L2","L3","L4"]}`，须遵循既有层序，不能借裁切重排。

## 可执行核查与提示词导出

标准库脚本可检查引用/层序/关系并导出该视图的固定陈列：
```powershell
python scripts/scene_spec.py validate path/to/scene-spec.json
python scripts/scene_spec.py render path/to/scene-spec.json --view V03_DETAIL
```

需要检查本机素材存在性时加 `--check-files`；相对路径以配置文件目录为根。脚本不看图片，也不能认证实际成图一致。导出的固定陈列放进生图提示词，并同时提供布局锚图和需要核对的商品图。

保存每个视图的实际提示词、引用素材、生成图路径和检查结果；旧图不覆盖。配置变动时记录变更，不能悄悄修改母配置去迎合失败图。

## 优先级与工具限制

用户当前明确修改 > 经确认的配置 > 锚图中已确认的部分。商品原图可证尺寸/外形优先于布局锚图的错误。冲突无法同时满足时明确指出，不能悄悄换货或换层。

遵守当前图像工具的引用上限；需要较多商品时按区域分批锚定或缩小本轮测试范围。不能因为引用超限就把少数商品复制到全店，再称为完整品类方案。
